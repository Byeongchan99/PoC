# 노드 기반 농장 경영 게임 POC 기획서

이 문서는 Claude Code가 Unity 6 프로젝트에서 POC를 구현하기 위한 기획 및 작업 지시서다. 사용자(Bychan)와의 사전 논의를 통해 결정된 사항들을 포함한다.

---

## 1. 게임 개요

### 1.1 컨셉
- **장르:** 노드 기반 농장 경영 시뮬레이션
- **참고작:** Stacklands, Upload Labs, Factorio
- **코어 루프:** 노드를 연결해 자원 생산 → 자원 판매로 돈 획득 → 돈으로 설비/스피릿 확장

### 1.2 주요 용어
- **Spirit (스피릿):** 작업을 수행하는 캐릭터. 원래 기획서의 "포켓몬"을 자체 IP화한 명칭. 코드 전반에서 `Spirit`으로 통일.
- **Facility (설비):** 자원을 생산/가공/저장하는 노드.
- **Node (노드):** 그래프 상의 모든 객체의 일반 명칭. Facility, Spirit 등이 모두 노드의 일종.
- **Port (포트):** 노드의 입출력 지점. 자원이 들어오는 입력 포트와 나가는 출력 포트가 있다.
- **Connection (연결선):** 두 포트를 잇는 와이어. 자원이 흐르는 경로.

## 2. POC 범위

### 2.1 포함되는 설비 노드 (6종)
1. **양수기 (Pump)** — 물 스피릿 배치 → 물 생산
2. **재배기 (Cultivator)** — 풀 스피릿 배치 → 씨앗 생산
3. **농장 (Farm)** — 씨앗 + 물 → 작물 생산
4. **창고 (Warehouse)** — 자원 저장 (POC에서는 고정 슬롯 N개로 단순화)
5. **시장 (Market)** — 자원 → 돈으로 변환
6. **주방 (Kitchen)** — 불 스피릿 + 작물 → 식량 생산

### 2.2 포함되는 자원 (5종)
- 물 (Water)
- 씨앗 (Seed)
- 작물 (Crop)
- 식량 (Food)
- 돈 (Money)

### 2.3 포함되는 스피릿 속성 (3종)
- 물 (Water) — 양수기에 배치
- 풀 (Grass) — 재배기에 배치
- 불 (Fire) — 주방에 배치

### 2.4 POC에서 제외되는 항목
- 식당, 아르바이트 노드
- 뽑기 시스템 (스피릿 획득)
- 스피릿 사망/리스폰 시스템
- 설비 업그레이드 시스템
- 스피릿 경험치/레벨업 시스템
- 세이브/로드

이 항목들은 POC 검증 이후 후속 마일스톤으로 미룬다.

## 3. 핵심 시스템 사양

### 3.1 자원 흐름 (분배 정책)
- **균등 분배 방식 채택.**
- 한 출력 포트가 여러 입력 포트에 연결된 경우, 자원은 균등하게 나뉘어 들어간다.
- **적응형 분배:** 받는 쪽 중 일부가 가득 차 있으면, 가득 찬 쪽은 스킵하고 나머지에만 전달한다.
- **소수 자원 처리:** 내부적으로 자원량을 `float`로 누적하고, 1.0 이상이 되었을 때 정수 1개를 전달하는 방식으로 처리한다. (Factorio의 splitter와 유사한 방식)

### 3.2 시간 처리
- **고정 틱(Fixed Tick) 기반.** 매 프레임 자원을 갱신하지 않는다.
- 기본 틱 간격은 **0.5초~1초** (Inspector에서 조정 가능하도록).
- 매 틱마다 모든 Connection을 순회하며 자원을 이동시킨다.

### 3.3 노드 그래프 UI
- **uGUI (Canvas 기반).** UI Toolkit이 아니라 익숙한 uGUI로 구현.
- 노드는 카드 형태로 Canvas 위에 배치된다.
- 드래그로 노드 이동, 포트 클릭 → 드래그 → 다른 포트에 드롭으로 연결 생성.
- **자원 흐름 시각화:** 연결선만 표시. 와이어 위에 자원 아이콘이 흐르는 등의 효과는 POC에서 제외.

### 3.4 설비 노드 레이아웃 (UI 요구사항)
각 설비 노드는 다음 요소를 표시한다:
1. 이름
2. 레벨 (POC에서는 1로 고정)
3. 이미지 (아이콘)
4. 현재 자원 칸 (입력 포트, 설비별로 개수 다름)
5. 작업 능력 (생산 속도)
6. 생산 자원 칸 (출력 포트, 설비별로 개수 다름)
7. 할당된 스피릿 (필요한 설비만)
8. 업그레이드 버튼 (POC에서는 비활성화 상태로 배치만)

### 3.5 스피릿 노드 레이아웃 (UI 요구사항)
각 스피릿 노드는 다음 요소를 표시한다:
1. 이름
2. 레벨 (POC에서는 1로 고정)
3. 경험치 (POC에서는 0으로 고정)
4. 속성 (Water/Grass/Fire)
5. 공격력 (POC에서는 표시만, 사용 안 함)
6. 작업 능력
7. 현재 체력 / 전체 체력 (POC에서는 표시만)
8. 현재 포만감 / 전체 포만감 (POC에서는 표시만)

### 3.6 스피릿 → 설비 배치
- 드래그 앤 드롭으로 스피릿 노드를 설비 노드에 할당.
- 설비별로 받을 수 있는 스피릿 속성이 정해져 있음 (양수기는 Water만, 재배기는 Grass만, 주방은 Fire만).
- 스피릿이 배치되어야 작업이 시작되는 설비: 양수기, 재배기, 주방.
- 농장, 창고, 시장은 스피릿 없이 작업 가능.

### 3.7 상점/구매 시스템
- 화면 상단/하단에 "현재 돈" 표시.
- "상점 버튼" 클릭 시 구매 가능한 설비 목록 팝업.
- 돈을 차감하고 새 설비 노드를 Canvas에 생성.
- 뽑기 버튼은 POC에서 제외.

## 4. 아키텍처 가이드

### 4.1 데이터와 로직 분리
- **데이터 (ScriptableObject):** 자원/설비/스피릿의 정적 정보. 인스펙터에서 밸런싱 조정.
- **런타임 인스턴스 (MonoBehaviour 또는 일반 클래스):** 실제 게임에서 동작하는 객체. 데이터를 참조해서 행동.
- 이렇게 분리하면 디자이너(또는 본인)가 코드 수정 없이 SO 에셋만으로 밸런싱 가능.

### 4.2 권장 클래스 구조
```
Data Layer (ScriptableObject)
├─ ResourceData      : 자원 종류별 메타데이터
├─ FacilityData      : 설비 종류별 메타데이터
└─ SpiritData        : 스피릿 종족별 메타데이터

Graph Core (일반 C# 클래스, MonoBehaviour 아님)
├─ NodeBase          : 모든 노드의 추상 기반
├─ Port              : 입출력 포트
├─ Connection        : 두 포트 간의 연결, 자원 이동 처리
└─ NodeGraph         : 전체 그래프 상태 관리

Runtime (MonoBehaviour)
├─ FacilityNode      : 설비 노드 런타임 인스턴스
├─ SpiritNode        : 스피릿 노드 런타임 인스턴스
└─ ResourceFlowSystem: 매 틱마다 모든 Connection 갱신

UI (MonoBehaviour, uGUI)
├─ FacilityNodeView  : 설비 노드 시각화
├─ SpiritNodeView    : 스피릿 노드 시각화
├─ ConnectionView    : 연결선 시각화
├─ NodeDragHandler   : 노드 드래그 처리
├─ PortConnectHandler: 포트 클릭→드래그→드롭으로 연결 생성
└─ ShopUI            : 상점 팝업
```

### 4.3 SOLID 및 코드 스타일
- 클래스와 메서드는 작은 단위로 분리 (단일 책임 원칙).
- 비전공자도 이해할 수 있게 변수명/메서드명을 명확하게.
- 어려운 로직에는 주석 필수. 메서드마다 무슨 역할인지 자세히 설명.
- 명명 규칙은 Unity 공식 가이드라인 (PascalCase 클래스/메서드, camelCase 필드, `_camelCase` 또는 `m_` 같은 prefix는 프로젝트 일관성에 맞춰).
- `[SerializeField]` 활용해서 디버깅용 수치를 인스펙터에서 조정할 수 있게.
- **DontDestroyOnLoad 기반 싱글톤 사용 자제.** 필요시 씬 단위 매니저나 ScriptableObject 기반 서비스 로케이터 패턴 권장.
- **리플렉션 자제.**

## 5. 작업 순서 (마일스톤)

각 단계가 끝날 때마다 동작 검증 후 다음 단계로 넘어간다.

### 1단계: 데이터 정의 (현재 시작점)
ScriptableObject 및 enum 정의. 아직 게임 로직 없음.

작성할 파일:
1. `ResourceType.cs` (enum)
2. `SpiritElement.cs` (enum)
3. `ResourceStack.cs` (직렬화 가능 구조체)
4. `ResourceData.cs` (ScriptableObject)
5. `SpiritData.cs` (ScriptableObject)
6. `FacilityData.cs` (ScriptableObject)

검증: 인스펙터에서 양수기/농장/물스피릿 등 SO 에셋을 만들어 데이터를 채울 수 있는지 확인.

### 2단계: 노드 그래프 코어 (UI 없이 콘솔 검증)
- `NodeBase`, `Port`, `Connection`
- `ResourceFlowSystem` (틱 기반 자원 이동)
- 콘솔 로그로 "양수기에서 1초마다 물 1개 생성됨" 확인.

검증: UI 없이 코드만으로 그래프를 구성하고, 자원이 흐르는지 Debug.Log로 확인.

### 3단계: 노드 UI
- 노드 카드 표시 (uGUI)
- 입출력 포트 시각화
- 드래그로 노드 이동

### 4단계: 연결 UI
- 포트 클릭 → 드래그 → 다른 포트에 드롭으로 연결 생성
- 연결선(와이어) 렌더링 (UILineRenderer 또는 자체 구현)
- 연결 검증 (출력→입력만, 같은 자원 타입만)

### 5단계: 스피릿 시스템
- 스피릿 노드 표시
- 설비에 드래그 앤 드롭으로 할당
- 속성 매칭 검증 (Water 스피릿 → 양수기에만)
- POC에서 포만감/체력은 UI 표시만, 감소 로직은 생략

### 6단계: 상점/구매 UI
- 현재 돈 표시
- 상점 팝업
- 돈 차감 및 새 설비 노드 생성

## 6. POC 검증 시나리오

POC가 완성되면 다음 시나리오가 동작해야 한다:

1. 게임 시작 시 일정 금액과 기본 스피릿 몇 마리가 주어진다.
2. 상점에서 양수기, 재배기, 농장, 창고, 시장을 구매한다.
3. 양수기에 물 스피릿을 배치한다.
4. 양수기 출력 → 농장 입력(물 슬롯) 연결.
5. 재배기에 풀 스피릿을 배치한다.
6. 재배기 출력 → 농장 입력(씨앗 슬롯) 연결.
7. 농장에서 작물이 생산되기 시작한다.
8. 농장 출력 → 창고 입력 연결.
9. 창고 출력 → 시장 입력 연결.
10. 시장에서 돈이 생산된다.
11. 주방을 구매하고 불 스피릿을 배치한다.
12. 농장 출력 → 주방 입력 연결 (이때 농장의 작물 출력은 창고와 주방으로 균등 분배되어야 함).
13. 주방에서 식량이 생산되기 시작한다.

## 7. 사용자 선호사항 (필수 준수)

- Unity 6 기반.
- 스크립트 작성 전 어떤 스크립트를 작성할지 사용자에게 확인받을 것.
- 디버깅용 수치는 `[SerializeField]`로 인스펙터에서 조정 가능하게.
- 사용자가 주석 처리한 코드는 무시하고 수정 진행.
- 일관된 명명 규칙 (Unity 공식 가이드라인).
- 클래스/메서드는 SOLID 원칙에 따라 작게.
- 비전공자도 이해할 수 있는 코드 작성.
- 어려운 코드에 주석 필수, 메서드마다 역할 설명.
- 실무 구현 방식 추천 포함.
- 최적화/성능 고려한 추천.
- 파일 시스템 관련 작업 제외.
- 주석에 이상한 아이콘 사용 금지.
- DontDestroyOnLoad 기반 싱글톤 자제.
- 리플렉션 자제.
- 사용자는 한국어로 소통한다.

## 8. 다음 액션

Claude Code는 이 문서를 읽은 후 **1단계: 데이터 정의**부터 시작한다.

작성 시작 전 사용자에게 다음을 확인:
- 폴더 구조 제안 (예: `Assets/Scripts/Data/`, `Assets/Scripts/Graph/`, `Assets/Scripts/Runtime/`, `Assets/Scripts/UI/`)

- 기존 프로젝트 폴더 구조와의 정합성
