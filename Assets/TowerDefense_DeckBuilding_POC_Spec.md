# 덱 빌딩 타워 디펜스 POC 개발 명세서

> Claude Code용 기획 및 개발 명세서
> 본 문서는 Unity 6 기반 POC 개발을 위한 것이며, 모든 기획 결정사항과 기술적 요구사항을 포함합니다.

---

## 1. 프로젝트 개요

### 1.1 게임 개요
- **장르**: 타워 디펜스 + 덱 빌딩
- **엔진**: Unity 6
- **뷰**: 2D 그리드 (POC 단계 단순화, 향후 3D 또는 아이소메트릭 확장 가능성)
- **개발 목적**: Proof of Concept (핵심 루프 검증)

### 1.2 핵심 컨셉
- 그리드 기반의 2D 타워 디펜스
- 벽과 타워를 "카드"로 저장, 카드를 사용하여 설치
- 카드 제작 시스템으로 플레이어가 덱을 구성
- 준비 페이즈 ↔ 전투 페이즈 반복 진행

---

## 2. 코어 루프

```
[게임 시작]
    ↓
[준비 페이즈]
  ├─ 코스트 10 수급 (이전 라운드 잔여 코스트 누적)
  ├─ 카드 제작 (선택)
  ├─ 벽 설치 (드래그 → 드롭 → 확정 버튼)
  ├─ 타워 설치 (드래그 → 즉시 설치)
  └─ [전투 시작 버튼] 클릭
    ↓
[전투 페이즈]
  ├─ 적 자동 스폰
  ├─ 타워 자동 공격, 적 자동 이동
  ├─ 플레이어 관여 불가
  └─ 모든 적 처치 시 승리 / 플레이어 HP 0 시 패배
    ↓
[다음 라운드 준비 페이즈로 복귀]
(사용하지 않은 카드는 유지됨)
```

### 2.1 승패 조건
- **승리**: 라운드의 모든 적 처치
- **패배**: 플레이어 HP 0 (기본 10, Inspector 수정 가능)
- 적이 목표 지점 도달 시 적의 공격력만큼 플레이어 HP 감소

## 3. 데이터 구조

### 3.1 카드 (Card)
모든 카드는 **3가지 속성**으로 구성:

| 속성 | 설명 |
|------|------|
| 종류 1 | 벽(Wall) / 타워(Tower) |
| 종류 2 | 벽: 테트로미노 모양 7종 / 타워: 공격 방식 3종 |
| 효과 | 없음 / 속성별 효과 4종 중 1개 |

**ScriptableObject로 구현 권장** (에디터에서 카드 데이터 편집 가능)

### 3.2 벽 (Wall)
- **형태**: 테트로미노 4칸 블록 7종류 (I, O, T, S, Z, L, J)
- **속성**:
  - 적 통과 불가
  - 파괴 불가 (무적)
  - 우클릭으로 회전 가능
  - 적의 진로를 완전히 차단할 수 없음
- **설치 제약**: 벽 하나당 타워 1개까지 설치 가능

**벽 효과 (택 1)**:
1. 효과 없음
2. 해당 벽 위 타워에게 공격력 추가 (고정값, Inspector 수정 가능)
3. 해당 벽 위 타워에게 사거리 추가 (고정값, Inspector 수정 가능)
4. 해당 벽 위 타워에게 공격 속도 추가 (고정값, Inspector 수정 가능)

### 3.3 타워 (Tower)
- **설치 조건**: 벽 위에만 설치 가능, 벽 하나당 타워 1개

**타워 스탯** (모두 Inspector 수정 가능):
- 공격력
- 사거리 (실수값 월드 거리 단위)
- 공격 속도

**타워 종류 (공격 방식)**:
1. **화살 타워**: 단일 타겟 투사체 공격
2. **레이저 타워**: 단일 타겟 지속 공격
   - 타겟이 사거리 들어오는 순간부터 조준
   - 타겟이 죽거나 사거리 밖으로 나갈 때까지 계속 공격
   - 매 0.1초마다 (공격력 × 0.1) 피해 적용
3. **포탄 타워**: 범위 피해 투사체
   - 폭발 반경: 실수값 (Inspector 수정 가능, 칸 단위 아님)
   - 범위 내 모든 적에게 동일한 피해

**타워 타겟 선택**: 가장 먼 적 (= 목표 지점에 가장 가까운 적)

**타워 효과 (택 1, 모든 수치 Inspector 수정 가능)**:
1. 효과 없음
2. 추가 피해: 고정 +5
3. 슬로우: 이동 속도 50% 감소, 2초 지속
4. 기절: 1초 지속

### 3.4 적 (Enemy)
**스탯** (모두 Inspector 수정 가능):
- 체력
- 공격력 (목표 도달 시 플레이어 HP에 입히는 피해)
- 이동 속도

**이동 규칙**:
- 그리드 칸과 칸 사이 직선 이동 (대각선 이동 불가)
- 목표 지점까지 최단 거리 이동
- 벽 통과 불가
- A* 알고리즘으로 경로 탐색

## 4. 카드 제작 시스템

### 4.1 제작 흐름 (3단계 선택)
```
1. 종류 1 선택: 벽 or 타워
2. 종류 2 선택: 랜덤 3개 선택지
   - 벽: 7종 중 3개
   - 타워: 3종 (POC에서는 전부 표시)
3. 효과 선택: 랜덤 3개 선택지 (4종 중 3개)
```

### 4.2 제작 비용 (ScriptableObject 수정 가능)
- **기본 제작 비용**: 5
- **효과 없음**: +0 (최종 5)
- **효과 있음**: +1 (최종 6)
- 모든 수치는 테스트 과정에서 계속 조정되므로 **ScriptableObject 또는 Inspector**에서 수정 가능해야 함

### 4.3 코스트 수급 규칙
- 준비 페이즈마다 10 수급 (Inspector 수정 가능)
- **코스트 누적 방식** (사용하지 않은 코스트는 다음 라운드로 이월)

### 4.4 카드 제작 UI
- 준비 페이즈 중 언제든지 "카드 제작" 버튼 클릭 가능
- 클릭 시 화면 중앙에 제작 패널 모달 오픈
- 3단계 순차 선택 진행

### 4.5 초기 손패 (게임 시작 시 제공)
- 효과 없는 벽 카드: 3장
- 효과 없는 타워 카드: 3장
- 해당 수치는 Inspector에서 수정 가능

### 4.6 손패 관리
- 최대 크기: 무제한 (POC)
- 사용하지 않은 카드는 다음 라운드로 유지

## 5. 페이즈 시스템

### 5.1 준비 페이즈
- 코스트 수급 (누적)
- 카드 제작 가능
- 벽 설치 가능 (드래그 → 드롭 → 확정 버튼)
- 타워 설치 가능 (드래그 → 즉시 설치)
- "전투 시작" 버튼으로 전투 페이즈 진입

### 5.2 전투 페이즈
- 적 자동 스폰
  - 스폰 위치: 고정 1곳
  - 스폰 방식: 일정 간격 순차 스폰 (Inspector 수정 가능)
- 타워 자동 공격
- 적 자동 이동 (준비 페이즈에서 확정된 경로 사용)
- **플레이어 관여 불가**
- 벽/타워 설치 불가, 카드 제작 불가
- 모든 적 처치 시 다음 준비 페이즈로

### 5.3 라운드 진행 (스케일링)
라운드마다 적 스케일링 증가 (Inspector 수정 가능):
- 적 수: 이전 라운드 + 2
- 적 체력: 이전 라운드 × 1.2

## 6. 설치 시스템

### 6.1 벽 설치
```
1. 손패에서 벽 카드 드래그 시작
2. 그리드 위로 드래그 중:
   - 다른 벽과 겹치면: 자동 취소 (드래그 상태 복귀 가능)
   - 우클릭으로 회전 가능
3. 그리드에 드롭:
   - 경로 검증 (A* 실행)
   - 경로 차단 시: 빨간색 표시, "설치 확정" 버튼 비활성화
   - 빨간색 상태에서 다시 드래그하여 위치 조정 가능
4. "설치 확정" 버튼 클릭:
   - 경로 최종 확정 (전투 페이즈 시 해당 경로 사용)
   - 카드 소비 (이 시점에 소비)
```

**제약**:
- 벽은 하나씩 확정 (여러 벽 동시 확정 불가)
- POC에서는 벽 제거 기능 없음

### 6.2 타워 설치
- 드래그 → 드롭 시 **즉시 설치** (확정 버튼 없음)
- 벽 위에만 드롭 가능
- 이미 타워가 설치된 벽에는 설치 불가

## 8. 기술 요구사항

### 8.1 개발 환경
- Unity 6
- C# 스크립트
- 필요 시 ScriptableObject 적극 활용

### 8.2 코드 가이드라인
- **네이밍**: Unity 공식 가이드라인 준수 (PascalCase for public, camelCase for private)
- **클래스/메서드 크기**: 작게 나눠 가독성 확보 (SOLID 원칙 준수)
- **주석**: 이해 어려운 코드에 반드시 주석, 메서드마다 역할 설명
- **주석 아이콘 사용 금지** (이모지 등)
- **비전공자도 이해 가능**한 수준으로 작성

### 8.3 필수 구조 제약
- **DontDestroyOnLoad 기반 싱글톤 사용 자제**
  - 씬 내에서 Inspector에 직접 할당하거나, 씬 단위 매니저 사용 권장
- **Reflection 사용 자제**
- **파일 시스템 관련 기능 금지** (저장/로드 등 POC에서 제외)

### 8.4 디버그 편의 기능 (필수)
개발 속도를 위해 아래 기능 반드시 포함:

1. **Scene 뷰 Gizmo**
   - 현재 적들의 경로 표시
   - 타워 사거리 원으로 표시
   - 그리드 칸 시각화

2. **Inspector ContextMenu / 디버그 버튼**
   - "카드 제작 코스트 획득" (코스트 즉시 추가)
   - "적 모두 제거"
   - "타임 스케일 조절" (슬라이더 또는 버튼)

3. **Inspector 수치 조정**
   - 모든 스탯, 효과 수치, 비용, 스케일링 값
   - 그리드 크기 및 시작/목표 지점
   - ScriptableObject 활용 권장

### 8.5 성능 고려사항
- A*는 벽 드롭 시점과 설치 확정 시점에만 실행 (매 프레임 실행 금지)
- 전투 페이즈 시작 시 경로 1회 확정 후 재계산 없음
- 타워 공격 간격은 Coroutine 또는 Timer 기반 (매 프레임 체크 지양)
- 적 다수 상황 고려하여 오브젝트 풀링 고려 (투사체, 적)

## 9. 개발 순서 (추천 로드맵)

각 단계마다 **플레이 가능한 상태**를 유지할 것.

### [1단계] 그리드 시스템 + 적 이동
- `GridSystem`: 그리드 데이터 관리, 좌표 변환
- `GridVisualizer`: Gizmo + 런타임 렌더링
- `PathFinder`: A* 길찾기 알고리즘
- `Enemy`: 기본 클래스 (스탯, 이동)
- `EnemySpawner`: 스폰 담당
- **검증**: 적이 시작점 → 목표점 잘 이동하는지

### [2단계] 벽 설치 + 경로 재계산
- 벽 데이터 및 설치 로직
- 테트로미노 7종 구현
- 드래그 앤 드롭 + 우클릭 회전
- 경로 검증, 빨간색 표시
- 설치 확정 버튼
- **검증**: 벽 설치 시 적이 우회 / 완전 차단 시 설치 거부

### [3단계] 타워 설치 + 공격 (화살만)
- 타워 기본 클래스
- 화살 타워 공격 로직
- 타겟 선택 (가장 먼 적)
- 벽 위 설치 제약
- **검증**: 타워가 적 처치

### [4단계] 카드 시스템
- Card ScriptableObject
- 손패 UI
- 드래그 앤 드롭 기반 카드 사용
- 초기 손패 제공
- **검증**: 카드 사용 → 벽/타워 설치 흐름

### [5단계] 카드 제작 UI
- 카드 제작 모달 패널
- 3단계 선택 로직
- 코스트 시스템
- 코스트 누적 처리
- **검증**: 카드 제작 → 손패 추가

### [6단계] 나머지 타워 2종 + 효과 시스템
- 레이저 타워, 포탄 타워
- 벽 효과 (공/사거리/공속 버프)
- 타워 효과 (추가피해/슬로우/기절)
- **검증**: 모든 카드 조합 동작

### [7단계] 페이즈 전환 + 라운드 시스템
- GameManager (씬 매니저)
- 준비 ↔ 전투 페이즈 전환
- 라운드 스케일링
- 승패 판정, UI 연동
- **검증**: 전체 루프 완성

## 10. 질문/애매한 부분 발생 시

Claude Code가 구현 중 애매한 점이 발견되면 **임의로 결정하지 말고 질문**할 것.
예상되는 추가 논의 지점:
- UI 스타일 (POC 수준으로 단순 유지)
- 파티클/사운드 (POC에서는 제외)
- 타워 강화 시스템 (POC 제외, 추후 확장)

## 11. POC 제외 항목 (명시적 제외)

아래 기능들은 **POC에서 구현하지 않음**:
- 타워/벽 강화 시스템
- 카드 등급 시스템
- 전투 페이즈 중 플레이어 관여
- 사운드, 파티클, 고급 VFX
- 세이브/로드 (파일 시스템 기능 금지)
- 벽/타워 제거 기능
- 메인 메뉴, 씬 전환
- 난이도 설정
